# 風格指南

整理自 Dex 的公開教材（DataDreamers 學員專題手冊、midterm-mvp-template、de-course、爬蟲課程教材）與本 repo 已產出的計畫書。

## 核心心法

> 「業界專案不是把技術秀出來，是把情境、痛點、解法（最優解和最快解）、遇到的技術問題和如何處理等講清楚。」

- 對象是**轉職者**：假設讀者有動機但沒有業界經驗，先講「為什麼」，再講「怎麼做」。
- 目標是**面試作品集**：每份教材最後都要能回答「這對履歷／面試有什麼幫助」。
- 專題分三級，教材要把學員往第三級推：

| 等級 | 樣貌 | 面試結果 |
| --- | --- | --- |
| 作業 | Notebook 跑得起，沒有架構圖，demo 只能手動 | 看不到亮點 |
| 作品 | 有敘述、能持續執行、技術棧豐富 | 跟其他人差不多 |
| MVP | 有架構圖、歷史紀錄、監控與下一步，能講為什麼選 A 不選 B | 面試官想深入了解 |

## 文件結構慣例

1. **開頭一句話講目標**：用引言或第一段直接寫「這份文件讓你做到什麼」。
2. **大量用表格**：選題、步驟、欄位、指標、時程、風險都用表格，欄位固定為「項目／做什麼／為什麼／產出」。
3. **每個步驟三件事**：目標 → 做法 → 產出（或「✅ 完成標準」）。
4. **讀者狀態路由**：長文件提供「你目前的狀態 → 必讀 → 下一步」表，讓不同進度的人各取所需。
5. **檢核點**：時程表每個階段都有可交付的檢核點，而不只是工作內容。
6. **過往案例**：附學長姐作品或真實情境，並給「看完回答 3 個問題」之類的引導。
7. **亮點設計**：專題要有一個可比較的實驗或決策（例如三元分類 vs 雙層二元分類），讓學員能講「為什麼這樣選」。
8. **風險與對策表**：計畫類文件都附，含「進度落後」的備案。
9. **誠實標註**：估計值、未驗證的數字、合成資料的限制都要寫明。

## 語氣

- 繁體中文、口語但精準；短句，一段不超過三句。
- 直接對學員說話（「你」），不寫空泛的形容詞，給數字、工具名、檔名。
- 技術名詞保留英文，第一次出現時附中文說明。

## 教學設計慣例

- **固定骨架**：Data Pipeline 六階段、ML 六步驟（資料收集 → 清理與 EDA → 特徵工程 → 訓練 → 驗證 → 判讀），讓學員「再也不會不知道從哪開始」。
- **Starter repo**：給可 fork 的範本，含 README、task.md、.gitignore、requirements.txt、.env.example；講師材料放 `_instructor/`。
- **情境題**：用產業情境（餐飲 POS、電商比價、金融客訴、串流推薦、叫車熱點、求職媒合、新聞輿情、不動產）對應業界職位。
- **復盤**：每個 sprint 末用 KPT 或 4Ls，期末對照 Demo Day 評分表與履歷升級 checklist。

## 文件版本

- 同一主題常需要兩個版本：**含程式版**（給實作者）與**無程式版**（給審核者、主管或非技術讀者）。
- 時程預設：短版 1–1.5 個月，完整版 2–2.5 個月（含一週緩衝）。
