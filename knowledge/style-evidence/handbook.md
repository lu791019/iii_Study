# Dex 寫作與教學風格觀察（來源：學員專題實戰手冊）

1. **用「你」直接對學員說話，語氣像教練不像老師**——第二人稱、口語、偶爾帶點幽默。例：「爬蟲合規問題要看 robots.txt + 不要爬太狠（你不是要做 DDoS）」。
2. **每章開頭一段引言（blockquote）點出這章解決什麼**，常帶一句心法。例：「> 復盤是把『我做了一個專題』轉成『我學到了 X』的關鍵動作。」
3. **把業界價值放在技術前面，反覆強調「故事比技術重要」**。例：「選一個『跟你過去工作 / 生活最有連結』的題目……故事比技術重要。」
4. **永遠用面試官的眼光來說明為什麼要做**，每個要求都連到面試或履歷。例：「沒上排程的話，面試官比較難從你的 demo 感受到工程價值」；「協作能力比技術深淺更難在履歷上看見，但在面試裡卻會被一眼看穿。」
5. **❌ / ✅ 對照範例**（爛 vs 好的 commit、模糊 vs 具體的 persona、履歷寫法）。例：「❌ 太模糊：『年輕的音樂愛好者』 ✅ 好：……」；「❌ 不要寫：『使用 Python 完成了一個專案』」。
6. **大量表格與決策樹**：選型、卡關、分工都做成表或 ASCII 樹。例：「你們是？├ 第一次跑專案、想簡單一點 → Trello」。
7. **「卡關處方」表（卡關 → 處方），解法短而具體**。例：「| 進度落後 | **砍 scope** 不是熬夜 — 砍掉 next-to-have |」。
8. **把失敗或縮減說成正常且聰明，降低學員焦慮**。例：「砍 scope 不是失敗 — 是聰明。業界 PM 一年砍幾十次。」；「第一次做通常會嚇到分數比想像低 —— 那才正確。」
9. **語氣溫和的「小提醒 / 建議習慣」，不用命令或責備**。例：「**一個小提醒**：很多人交作業時就停在『手動跑一次』」；「**建議習慣**：Raw 永遠保留……多一份備份，安心很多。」
10. **把誠實當成評分標準**，反對「都很好」。例：「寫『都很好』『都很順』= 沒做 retro，誠實才有用。」；「你最後悔的 1 個決定？→ 不要說『都很好』，誠實得分高」。
11. **給降低門檻的選項，並明說預設值**（一般版 / 專業版、必做 / 非必要）。例：「💡 **沒選擇障礙就選一般版**。專題結束想升級時再 Transfer 到 org 也來得及」。
12. **每章結尾固定是「🎯 小作業」checkbox＋交付方式＋💡 提示**，接著是「下一步 →」連結。例：「**交付**：PR 連結貼到指定 channel。」
13. **Emoji 當作視覺路標而非裝飾**：章節分類（📐🎯🛠📚❓）、評分等級（❌🟡✅🏆🌱）、管線階段（📁📥💾⚙️🖥📡）、提示（💡⚠️💎）。正文句子內很少用。
14. **中英混用業界術語，不硬翻**（sprint、scope、owner、demo、PR、retro、nice-to-have），首次出現時用括號補中文或白話。例：「不寫死(hard code，也就是要用 function 或把參數拉出來使用)」。
15. **具體數字與時間預算**，讓建議可執行。例：「1.5 hr：互相認識 + 強項盤點」「Sprint Planning 每次限定 45-60 分鐘，嚴格計時」「打勾 ≥ 8 → 你準備好了。」
16. **用短句格言濃縮觀念**，常以對比句出現。例：「在 whiteboard 上花 1 小時，省 10 小時打 code。」；「設計階段發現的問題：免費。寫到一半發現的問題：要重構。demo 前發現的問題：要熬夜。」
17. **用學長姐過往作品與「學員原話」建立連結**，FAQ 先附原話再回答，回答以「先知道自己在哪個階段」來分步引導。例：「(原話：看了第0週的git專案的整體流程，老師寫的很多，可是我好像不太能理解……)」；「2. 再確認和建置各種工具 <-現在在這」。
18. **把業界對標寫成具體公司與職位，並提供「面試 5 秒講法」**。例：「💬 面試 5 秒講法：『我做了一個多門市 POS 庫存儀表板，每天自動產出補貨建議……』」。
19. **轉職者視角與個人品牌語氣**：自介強調走過彎路，結尾邀請互動而非推銷。例：「讓我們一起在轉折點上慢慢前行」；「最大的回饋是讓我知道：你做到哪了、卡在哪、需要什麼」。
20. **自稱「教練」，把 escalate 給教練視為正常流程**。例：「有人神隱 → 馬上 escalate 給教練，不要拖」；「同一張 P0 卡片 in-progress > 2 天 → 拉教練 + 把卡拆小」。

小缺點（仿寫時別複製）：章節編號互相引用時偶有錯位（07 章稱藍圖為「01」）、Sprint 週期與 WIP 數字在不同章不一致、偶有錯字（「溝通通句」）。
