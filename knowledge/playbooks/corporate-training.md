# 企業內訓課程設計手冊（YOLO／電腦視覺）

> 這份手冊說明 Dex 怎麼設計企業內訓的實作課：以一門影像物件偵測（YOLO）課為例，整理場次與模組、每一幕怎麼安排實作、環境怎麼準備、上課出狀況怎麼救，以及它跟一般轉職班差在哪裡。
> 之後要接企業內訓（尤其是 AI／ML 加 AI 輔助開發的主題）時，照這份走。
>
> 「規格是量出來的，不是猜的。」

**來源**：Dex 的一個私人課程 repo（某企業內訓客戶的影像物件偵測課，第 3–4 場的教材、學員包、講師手冊與改版規格），2026-08～09。下文用「企業內訓客戶」代稱客戶。第 1–2 場的教材不在 repo 裡。標「推論」的段落不是 repo 原文。

---

## 做完這份，你會做到

1. 把一門內訓課切成「每場一個主軸」，場與場之間只留一個交接物。
2. 用「幕」排出 2–3 小時的時間軸，並先寫好超時要砍什麼。
3. 設計一段「破案劇場」：埋伏筆 → 重現 bug → 拿證物 → 假設檢定 → 揭曉 → 收斂。
4. 準備一份不吃外網、零後端、有假模型保底的學員包，加上講師課前 checklist。
5. 把資安與權限教成一個有真實案例的段落，而不是一條條規則。

## 1. 課程全貌

| 場 | 主題 | 長度 | 學員帶走 |
| --- | --- | --- | --- |
| 1–2 | 資料標註＋在雲端 ML 平台訓練 YOLO-NAS | （教材不在 repo） | 一顆自己組的模型（ONNX） |
| 3 | **Vibe Coding 前端**：把模型變成瀏覽器推論台 | 3 小時 | 一個用自己模型、真的會動的推論台 |
| 4 | **Agentic Engineering：給 AI 裝上手腳**：規格驅動開發、E2E 自動測試、品質把關 agent | 2 小時 | 一支測試全綠的推論 API、一套上線判定流程 |

**三層能力地圖**（第 4 場收尾用）：

```
寫（描述需求，AI 寫程式）→ 做（給 AI 工具，讓它去操作）→ 判（定義標準，讓 agent 判定能不能上線）
```

### 設計決定（repo 原文）

- **訓練與推論分開講，交接點只有一個檔案**（`ckpt_best.onnx`）。原本規劃了「從前端觸發雲端訓練」，後來拿掉了，理由是混在一起會讓兩件事糊在一起。
- **主線選純前端**（單檔 HTML＋瀏覽器端推論引擎）：零後端、零安裝、不碰雲端權限，從零到看到框最快，錯誤也只在一個地方出現。比較接近正式環境的 API 架構，放到下一場再補。
- **最後一場從「AI 幫你寫」升級到「AI 幫你做」**：起因是講師在課前用 AI 開瀏覽器登入雲端主控台、在 CloudShell 打指令、幫三組備份模型，全程沒自己寫程式。這段過程直接拿來當開場教材。
- 舊版教材（「五種產出」版：評分台、推論 API、部署）**降級為備用素材，不刪**；進度快的時候當加碼題。

## 2. 設計心法

| 原則 | 意思 | 落地 |
| --- | --- | --- |
| 先量測，再讓 AI 寫 | 規格（輸入 shape、輸出、類別數、前處理）用工具量出來，寫進 `CLAUDE.md` 的「模型契約」，AI 照契約寫 | 第 0 輪量測、`inspect_onnx.py` |
| 成就感錨點 | 每場都要有一個「看得見、交得出去」的東西 | 推論台、全綠的 API |
| 分層除錯 | 說「模型爛」之前，依序排查部署層 → 訓練層 → 資料層 | 破案劇場、品質三關卡 |
| 真實事件當教材 | 自己課堂上真的發生過的 bug、開課前幾天的公開資安事件，都比編出來的例子有力 | BGR 事件、憑證外洩事件 |
| 假的先頂、真的再換 | 假模型的規格和真模型完全一樣，訓練沒完成的人也能把管線跑通 | `mock-yolonas.onnx` |
| 一次驗收一個 | 「迭代的單位是驗證，不是 prompt」 | 第三輪功能清單 |
| 實測過才寫進教材 | 規格裡每一個要學員做的步驟，接手的人都要自己實跑過一次 | 改版規格的鐵則 |

> ⚠️ 上一場的教訓：沒實測過的步驟（讓沒裝 CLI 的學員跑 CLI 指令）會在課堂上炸掉。實測結果和規格衝突時，**以實測附錄為準**。

## 3. 模組與時數

### 3.1 第 3 場（3 小時，三幕）

| 幕 | 時間 | 內容 |
| --- | --- | --- |
| 第一幕：先量測 | ~40 分 | 開場架構圖（訓練和推論是兩件事）→ Vibe Coding 三要素（目標、限制、驗收）→ 量測自己的模型，每組唸出三行規格 |
| 第二幕：假模型跑通＋AI 寫前端 | ~70 分 | 五分鐘拿到會動的東西 → 跟 Claude Code 四輪接力 → 座標對齊（認症狀） |
| 第三幕：真模型＋破案劇場 | ~60 分 | 換上真模型 → 破案劇場 → 資料面的差異討論 |
| 收尾 | ~10 分 | 15 項進度面板打勾、回家作業、預告 |

時間是比例參考，可以等比伸縮。

**進度落後時的犧牲順序**：深水區互動 > 介面功能 > 收尾。**第 0 輪量測和破案劇場絕不跳過。**

### 3.2 第 4 場（2 小時）

| 幕 | 時間 | 內容 | 誰動手 |
| --- | --- | --- | --- |
| 開場 | 20 分 | 回放「AI 操作雲端」實錄；定義 agentic engineering＋六原則 | 講師 |
| 01 權限與資安 | 15 分 | 風險四格 → 公開外洩案例 → 防備清單 → 臨時憑證 | 純講述 |
| 02 實戰一：SDD 開發鏈 | 60 分 | 需求 → 流程分析 → API 規格 → 設計審查 → FastAPI 實作 → 取依賴 → pytest 全綠 | 學員 |
| 03 實戰二：E2E | 20 分 | 裝瀏覽器 MCP → AI 測推論台三題 | 學員 |
| 04 實戰三：品質門檻 | 20 分 | 走讀 agent 三件套 → 四個劇本的判定 | 學員 |
| 收尾 | 5 分 | 四週回顧、六原則回收、雲端成果過期提醒 | 講師 |

**超時砍法**：實戰一的最後一棒改成「跑講師參考解的現成測試」；實戰三的「做自己的 agent」改成口頭帶過。

### 3.3 Agentic Engineering 六原則（第 4 場的骨架）

| # | 原則 | 常見錯誤 | 正確做法 |
| --- | --- | --- | --- |
| 1 | 需求先講清楚 | 「幫我做一個 XX」一句話丟過去 | 目標、限制、驗收三件事講完整 |
| 2 | 小步交付 | 一次要求全部做完 | 一次一個功能，驗收通過才做下一個 |
| 3 | 人在迴圈 | 圖方便全部放行 | 每個動作執行前審查，看懂才放行 |
| 4 | 驗證自動化，判斷留給人 | AI 說沒問題就當沒問題 | AI 跑測試、如實回報；嚴不嚴重由人判斷 |
| 5 | 確定性歸程式，模糊性歸模型 | 讓 AI 心算數字、憑感覺判定 | 數字歸 script、標準歸 skill、流程歸 agent |
| 6 | 最小權限、可稽核 | 一把高權限長期金鑰一路用到底 | 臨時憑證、最小權限、留下稽核紀錄 |

原則 1、2 在第 3 場練，3–6 在第 4 場各節練，每節開頭都標出對應的原則。

## 4. 實作安排

### 4.1 四輪接力（第 3 場，學員和 Claude Code 對話）

| 輪 | 學員給 AI 什麼 | 驗收 |
| --- | --- | --- |
| 第 0 輪 | 一段 prompt：自己找模型檔、照範本寫 `CLAUDE.md`、跑量測、把數字填進「模型契約」、用三句話總結後停下 | 抽組唸總結；打開 `CLAUDE.md` 檢查契約有沒有填上 |
| 第一輪 | 會動的殼：拖放圖片、畫在 canvas 上、顯示寬高，**先不做推論** | 畫面上有圖 |
| 第二輪 | 接模型：「照 CLAUDE.md 的契約，每一條都要遵守」，寫完先自己對照檢查 | 有框 |
| 第三輪 | 功能清單一次給完，AI 排隊做，**每做完一個就停下來給驗收** | 至少滑桿要過 |

重點講法：

- 「`CLAUDE.md` 每次啟動都會自動讀，規格寫一次就好，不用每輪重貼。」
- 「教材上那張資料夾樹是驗收清單，不是操作步驟。擺檔案是 AI 的事，驗收是你的事。」
- 描述壞掉的樣子要「有現象、有數字、有原文」，例如：圖有出來、框 0 個、Console 沒紅字、候選框 0。看到「跑不動」「怪怪的」這種描述，現場示範怎麼改寫。
- 「每拿到一個會動的版本就另存一份。改壞了回去重來，比往下修快。」

### 4.2 破案劇場（第 3 場的高潮）

| 步驟 | 做什麼 |
| --- | --- |
| 埋伏筆（第一幕） | 「規格有兩條印不出來：像素不除 255、通道順序是 BGR。第二條從 shape 完全看不出來，等一下它會回來咬人。」 |
| 重現案發現場 | 講師載入真模型，**故意關掉**推論台的 BGR 開關：畫面亂框、背景被高信心誤判 |
| 問全班 | 「模型爛，還是程式爛？你怎麼分？」先收集答案，不評論 |
| 拿出證物 | 投影訓練 log：驗證集的成績很好，代表訓練是成功的。訓練好、推論爛，問題就在中間的部署層 |
| 假設檢定 | 假設一「要除 255」→ 一開全滅 → 排除；假設二「通道順序」→ 打開 BGR → 框變乾淨 |
| 揭曉機轉 | 訓練管線用 OpenCV（BGR），瀏覽器 canvas 給的是 RGB；shape 一樣，量測工具看不出來，假模型只看亮度也驗不出來 |
| 收斂三句（板書） | ① 量測有盲區，契約要包含量不出來的部分 ② 假模型驗得了管線，驗不了前處理的全部 ③ 說模型爛之前，先對照訓練 log 排除部署層 |

接著講**資料層**：BGR 修好之後各組表現還是不同，就各組討論自己的資料，例如「資料量太少、目標縮到 640 後只剩幾個像素」「漏標，沒框到的目標被教成背景」「全部同一個場景，換個場地還能用嗎」。

> 💡 這個設計可以通用：**先讓一個真實 bug 在課堂上被重現，再用證據加排除法破案。**學員帶走的是除錯順序，不只是一個修法。

### 4.3 SDD 開發鏈（第 4 場實戰一，一棒一停）

起始包只有一份 `需求.md`（功能＋模型契約），講師參考解（全部產物＋6 條 pytest）不發給學員。

| 棒 | 學員做 | 對產物時要講什麼 |
| --- | --- | --- |
| 流程分析 skill | 跑 skill | 「CSV 沒有被拆成獨立端點，是 skill 內建的設計判準在把關」 |
| API 規格 skill | 跑 skill | 「description 每一條都對回需求的一句話，等一下每條都會變成一條測試」 |
| 品質審查 skill | 跑 skill | 「審查在寫碼之前，PASS 才准動手」；有阻斷的組照返工清單修 |
| 實作＋取依賴 | 骨架 → /health → /predict；用臨時憑證抓模型 | 第一條雲端指令跳出確認框時全場停下：「它在問你，看懂才按」 |
| 測試 | pytest＋curl | 「做完的定義是：測試全綠，而且親眼看過回應」 |

skill 的固定結構：`SKILL.md`（SOP）＋`rules/`（判準）＋`templates/`（報告樣板），學員課前複製到自己的 skills 資料夾。

### 4.4 E2E 三題（第 4 場實戰二）

| 題 | 教學點 |
| --- | --- |
| 載入模型與圖片，截圖回報 | 慢不等於當機（第一次推論本來就要等） |
| 檢查 console | AI 回報「有一個 404」，其實是 favicon，無害。**判斷錯誤重不重要的是你** |
| 掃信心閾值 | 閾值低時大量雜訊，高時框全消失。**漏抓在畫面上看不出來，畫面只會變乾淨** |

### 4.5 品質把關 agent（第 4 場實戰三）

三件套：`agents/mlops-gate.md`（角色、流程、紀律：不放水、不腦補）＋`skills/model-quality-gates/`（SOP、判準、報告樣板）＋`scripts/gate_check.py`（數字比大小交給程式算）。agent 放在專案的 `.claude/agents/`，進資料夾就生效，可以進版控給全團隊共用。

**三關卡判準**（課堂粗篩用的門檻，repo 原文）：

| 關卡 | 在防什麼 | 門檻 | 沒過時怎麼辦 |
| --- | --- | --- | --- |
| Gate 1 訓練品質 | 模型根本沒學到東西 | val mAP@0.50 ≥ 0.50 | 回訓練端：看資料量、目標大小、有沒有用預訓練權重 |
| Gate 2 資料體質 | 資料本身站不住；**漏標比少標更毒** | 訓練圖 ≥ 300 張，抽查漏標率 ≤ 5% | 先補標註再談訓練 |
| Gate 3 部署一致性 | 模型沒問題，部署層把它餵壞 | 部署端實測 recall ≥ 訓練 mAP − 0.15 | **模型先不要動**，逐項核對前處理 |

整體判定：三關全過＝GO；任一關 FAIL＝NO-GO；某關缺數據就標「無法判定」，整體最多給「有條件 GO」，並寫明要補量什麼。**確定的失敗不能被缺數據掩蓋**（開發 kit 時真的踩過這個 bug）。**要改門檻就改文件，不在現場通融。**

準備四個劇本讓學員各問一次（修正前、修正後、資料太少、漏標），讓四種判定結果都出現一次。

### 4.6 回家作業

- 第 3 場：每組依診斷改善資料（換場景加拍、解決小目標、補漏標）→ 重新訓練 → 用推論台拿同一批測試圖比對新舊模型。預告：「第一代模型會很爛，這正是重點，資料飛輪的意義在第二圈。」
- 第 4 場：想一個「有明確判斷標準」的工作，把 SKILL.md 的三個關卡寫出來（不用寫程式）。

## 5. 環境準備

### 5.1 學員包結構

```
學員包-0N/
├── 0N-教材-<主題>.html     單檔、雙擊就能開，圖用 base64 內嵌；投影跟自讀共用
├── README-先讀我.md        包裡有什麼、課前要裝什麼
├── demo/                   範例推論台＋假模型＋量測工具（推論引擎 vendor 進來，斷網也能跑）
├── <實戰起始包>/            只放需求文件
└── skills/ 或 agent-kit/   要發給學員的 skills 和 agent 範例
instructor/                 講師專用（不發）：講師手冊、診斷報告、參考解、模型備份
docs/                       改版規格、HANDOFF、實測紀錄
```

教材分兩部：**主線**（照著做）和**深水區**（「不用先讀，卡住再翻」，例如症狀對照表、交付前的檢查清單）。教材裡直接嵌入「課堂動線」框，上課投影教材照著走，講師手冊只留時間軸、講法細節和急救表。

### 5.2 課前通知（學員端，約 15 分鐘）

1. 解壓學員包，雙擊打開教材。
2. 照教材第 00 節做：每組派一個人下載模型；每個人先裝好 AI coding 工具，再**用教材裡的 prompt 讓 AI 幫你把剩下的環境裝好**。
3. 帶 2–3 張自己拍的測試圖（訓練資料以外的最好）。
4. ⚠️ 雲端上的訓練成果會在固定天數後自動刪除，請務必下載保存。

第 4 場的設定 prompt 也交給 AI 代辦：讀 README、裝 skills、驗環境、把上週的推論台資料夾搬進來並檢查模型檔在不在。**學員唯一要手動做的是：裝完重開工具，打得出 skill 指令就算驗收通過。**

### 5.3 講師課前 checklist

- [ ] 講師機起本機 http server，推論台開得起來
- [ ] 用真模型彩排破案劇場：開關打開框乾淨、關掉亂框
- [ ] 確認每組都拿得到自己的模型；拿不到的組準備假模型或講師的備份模型
- [ ] 投影解析度下，互動 Lab 操作得動
- [ ] 教室網路連得到推論引擎的 CDN；連不到就改用 vendor 版 demo
- [ ] 工具版本：AI coding 工具、Node 20+、Python 3、雲端 CLI 要夠新（舊版沒有臨時憑證登入指令）
- [ ] 抽一個**學員帳號**實際跑過授權流程（只用講師帳號驗過不算）
- [ ] 大檔案（約 200MB 的模型）準備三條備援：學員本機上週下載的、講師當天早上產的時效下載連結（**一定要當天產**，連結的壽命綁在登入 session 上）、隨身碟
- [ ] 發放用的 zip **用 Python 腳本打包**：macOS 的 zip 指令寫中文檔名時不設 UTF-8 旗標，Windows 解壓會亂碼甚至缺檔（真的有學員中招過；舊包發出去了就要重發）

### 5.4 課堂急救表（節錄）

| 狀況 | 處置 |
| --- | --- |
| 推論台開不起來 | 九成是雙擊用 `file://` 開的 → 改起 http server |
| 有組沒拿到模型 | 用假模型上課，或發講師的備份模型 |
| AI 工具裝不起來或額度用完 | 退回網頁版聊天 AI（prompt 通用，檔案改用複製貼上），或兩人共用一台 |
| skill 叫不出來 | 裝完沒重開工具 |
| 服務過載 | 等一分鐘重試，或先拿講師參考解對照著講 |
| AI 卡在「選資料夾」對話框 | 它做不到，學員自己點（單檔上傳它可以） |
| 瀏覽器 MCP 回報已在執行 | 砍掉殘留的 process 再試 |
| Windows 學員裝不起來 | 教材是在 macOS 實測的；先兩人共用一台，課後再個別處理 |
| 有人問「為什麼不從 export 端一勞永逸地修」 | 好問題，正解確實是這樣，但要重新匯出所有模型。順勢講「修正契約的遷移成本」 |

## 6. 資安段落怎麼教（第 4 場幕 1）

repo 的做法是**純講述，不在課堂建立任何金鑰**：

1. **風險四格**：金鑰是明文、AI 能跑任何指令、提示注入、不小心外洩（print、commit、log）。
2. **一個時效性強的公開案例**：開課前幾天剛好有一起雲端部署平台的憑證外洩事件。走一遍時間軸，唸出被外洩的金鑰種類，停一拍問：「這張清單跟你 `.env` 裡的東西重疊多少？」
3. **課堂討論兩題**：你的專案金鑰放在哪？今晚外洩了，你什麼時候會發現？多數人答不出第二題，順勢收在「帳單不該是你的警報」。
4. **防備清單表**（日常情境 → 風險 → 該做的防備），逐列問「這格你中了嗎」，比逐列唸有效。進階手段收在摺疊區，有人問才打開。
5. **結論**：外洩的都是長期金鑰，所以答案不是「小心保管」，而是**「能不用長期金鑰就不要用」**，改用跟主控台 session 綁在一起、會自己過期的臨時憑證。最小權限 policy 只當範例展示（只給特定 bucket 的讀取權和訓練工作的查詢權，不給任何刪除、終止、建立的權限）。

結語：「全程沒有建立任何長期金鑰。給權限、看紀錄、用完收回，這是資安的原則，也是所有授權工作的通則。」

## 7. 與一般轉職班的差異

repo 沒有直接比較兩者，下表是我**對照本知識庫其他 playbook 推論**出來的，標「原文」的格子才是 repo 裡寫的。

| 面向 | 一般轉職班（見 [course-design.md](course-design.md)、[workshop-design.md](workshop-design.md)） | 這門企業內訓 |
| --- | --- | --- |
| 總時數 | 21 集帶狀課＋工作坊，長期 | 4 場，每場 2–3 小時（原文） |
| 主線 | 一個專案貫穿整期、每集升級 | 一顆**學員自己組訓練出來的模型**貫穿四場（原文），場與場之間只交接一個檔案 |
| 終點 | 作品集、面試、履歷 | 能交出去的工具與流程（推論台、API、上線判定）（推論） |
| 資料 | 公開資料集、假資料 | 學員自己標註、自己拍的場域圖片（原文）；資料品質本身就是教材 |
| 環境 | 學員自備，課程從裝環境教起 | 雲端帳號由課程環境統一提供，學員帳號只看得到自己的資料夾（原文）；本機環境交給 AI 代裝 |
| 資安 | 講 `.env`、不要 commit secrets | 獨立一幕，講憑證生命週期、最小權限、可稽核（原文） |
| AI 的角色 | 輔助寫程式 | 課程主軸本身就是「怎麼把 AI 放進工程流程」（原文） |
| 失敗處理 | 降低焦慮、砍 scope | 把真實失敗當高潮來演（破案劇場），再升級成可重用的判準（原文） |
| 分組 | 13 人左右分 3 組，個人實作、團隊智囊 | 以組為單位（原文：三組，各自有不同的資料和類別） |
| 講師資產 | 講師指南、TA 簡報 | 講師手冊＋改版規格＋實測附錄＋HANDOFF，讓 AI 或下一位講師可以接手（原文） |

（推論）企業內訓的學員通常已經在職，關心的是「回去能不能用在工作上」，不是「面試怎麼講」。所以每一幕的收斂句都寫成可以帶回團隊的工作原則（「改門檻改文件」「數字歸 script」），而不是寫成履歷句。

## 8. 教學金句

- 規格是量出來的，不是猜的。
- 限制越具體，AI 猜的空間越小。
- 描述壞掉的樣子：有現象、有數字、有原文。
- 迭代的單位是驗證，不是 prompt。
- shape 量得出來的是規格，量不出來的才是坑。
- 說模型爛之前，先確認你沒把好模型餵壞。
- 漏標比少標毒，沒框到的目標會被教成背景。
- 能不用長期金鑰，就不要用長期金鑰。
- AI 負責誠實回報，判斷錯誤重不重要的是你。
- 數字歸 script、標準歸 skill、流程歸 agent。
- 確定的失敗不能被缺數據掩蓋。

## 9. 設計一門新內訓的 checklist

- [ ] 每場一個主軸，場與場之間的交接物只有一個
- [ ] 每場一個成就感錨點（看得見、交得出去）
- [ ] 時間軸用「幕」切，寫好超時砍法與絕不能跳過的段落
- [ ] 至少一段用真實 bug 或真實事件做成的劇場
- [ ] 假資料或假模型保底；外部依賴有離線備援
- [ ] 學員包：單檔教材＋README-先讀我＋起始包；參考解只留在講師端
- [ ] 環境設定盡量交給 AI 代辦，學員只做一個可驗收的動作
- [ ] 用學員帳號實測每個要學員做的步驟；實測結果寫進附錄
- [ ] 資安段落：案例 → 討論 → 防備清單 → 一句結論
- [ ] 課前通知模板、講師 checklist、急救表、雲端資源過期提醒
- [ ] 判準寫成文件和常數（不在現場通融）
