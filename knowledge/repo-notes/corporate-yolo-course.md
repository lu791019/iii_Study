# 企業內訓：YOLO 影像物件偵測課（私人 repo）

> **一句話用途**：為某企業內訓客戶開的影像物件偵測（YOLO）課，repo 收第 3–4 場的教材、學員包、講師手冊與改版規格。第 3 場用 Vibe Coding 把訓練好的 ONNX 模型做成瀏覽器推論台；第 4 場講 Agentic Engineering（規格驅動開發、E2E 自動測試、品質把關 agent）。

⚠️ 這是私人 repo，repo 名稱裡有客戶名，本知識庫的其他地方一律寫「企業內訓客戶」。裡面的雲端帳號資源名稱、學員憑證、真實模型都不能外流（帳密與模型本來就沒進版控）。

## 可借用的知識精華

1. **先量測，再讓 AI 寫**：用工具量出模型的輸入輸出，寫進 `CLAUDE.md` 的「模型契約」；之後每一輪都指著契約要功能，不必重貼規格。
2. **四輪接力**：第 0 輪讓 AI 自己整理專案 → 會動的殼 → 接模型 → 功能清單一次給、一次驗收一個。「迭代的單位是驗證，不是 prompt。」
3. **破案劇場**：先在第一幕埋伏筆，到第三幕重現 bug，再用訓練 log 當證物、排除法做假設檢定，最後板書收斂三句。把一個真實 bug 變成整堂課的高潮。
4. **分層除錯順序**：部署層 → 訓練層 → 資料層。說「模型爛」之前，先排除部署層。
5. **三關卡上線判準**：訓練品質、資料體質、部署一致性；缺數據最多給「有條件 GO」；確定的失敗不能被缺數據掩蓋；要改門檻就改文件。
6. **Agentic Engineering 六原則**：需求講清楚、小步交付、人在迴圈、驗證自動化但判斷留給人、確定性的事歸程式、最小權限且可稽核。
7. **資安段純講述**：用時效性強的公開案例 → 討論「你什麼時候會發現」→ 防備清單 → 結論「能不用長期金鑰就不要用」，改用臨時憑證。
8. **學員包設計**：單檔 HTML 教材雙擊就能開；假模型保底；推論引擎 vendor 進來可以離線跑；講師參考解只留在講師端；README-先讀我。
9. **環境設定交給 AI 代辦**：學員只做一個可驗收的動作（重開工具，打得出 skill 指令）。
10. **實測鐵則**：每個要學員做的步驟都要先實跑；實測和規格衝突時以實測附錄為準；要用學員帳號驗，不能只用講師帳號。
